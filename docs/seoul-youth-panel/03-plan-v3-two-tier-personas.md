# social-labs 정책 시뮬레이션 구현 계획 v3 — 2계층 페르소나(정적 + 디지털 트윈)

> 개정 사유: 제안하신 ① Nemotron-Personas-Korea = **정적 페르소나(static persona)**,
> ② 서울청년패널 = **생성형 에이전트/디지털 트윈(digital twin)**, ③ 두 패널을 결합한 정책
> 시뮬레이션 구조를 반영. 결론부터: **좋은 방향이며 설계 문서의 포지셔닝과도 정합**하다.
> 다만 두 데이터의 성격 차이에서 오는 **역할 분담과 타당성 경계**를 명확히 해야 한다.

---

## 1. 제안에 대한 평가 (먼저 솔직하게)

**강점 — 이 조합이 잘 맞는 이유**
- 설계 문서가 이미 *"Nemotron = 합성 정적 스냅샷 / Social Labs = 종단 궤적 에이전트"* 로 둘을 대비했는데, 제안은 그 대비를 **실제 두 계층으로 구현**하는 것이라 제품 비전과 일관됩니다.
- 서울패널의 약점(패널완결 ~3,762명·2시점뿐)을 Nemotron의 강점(**실제 인구분포에 정합한 600만+ 합성 페르소나**, 한국어·PIPA 안전)으로 보완 → **폭(대표성) × 깊이(실제 행동·결과)** 의 micro–macro 결합이 자연스럽게 성립.
- 둘 다 한국어 네이티브라 임베딩·프롬프트가 일관됨.

**핵심 경계 — 반드시 지켜야 할 한 가지**
- Nemotron 페르소나는 **완전 합성**이며 **시간축도, 실제 결과(소득·취업 변화)도, 정책 이용 이력도 없습니다.** 인구분포는 정확하지만 *행동·인과 관계*는 담고 있지 않습니다. 따라서 **정책효과의 "근거"는 디지털 트윈(실데이터)에서만 나오고, 정적 페르소나는 그 패턴을 "투영(projection)받아 확장"하는 역할**로 한정해야 합니다. 이 경계를 흐리면 "그럴듯하지만 근거 없는" 정책 추정이 됩니다. → §4에서 역할을 명시적으로 분리.

요약 평가: **채택 권장.** 단 "정적=폭/대표성·세그먼트, 트윈=깊이/인과 근거"라는 역할 분담을 아키텍처·UI·API 문서에 못박는 것이 성패를 좌우합니다.

## 2. 개정 아키텍처 — 2계층 페르소나

```
┌────────────────────── Social Labs 정책 시뮬레이션 ──────────────────────┐
│                                                                        │
│   [Tier 1] 정적 페르소나 (Static)        [Tier 2] 디지털 트윈 (Generative) │
│   Nemotron-Personas-Korea               서울청년패널 (실데이터)           │
│   · 합성 스냅샷, 시간축 없음             · 1·2차 실제 궤적 + 정책 이용/만족  │
│   · 서울·18~35세로 필터(유사 샘플)        · 반사실 응답 + 실제 사전/사후 근거  │
│   · 역할: 폭·대표성·세그먼트·확장 모집단    · 역할: 깊이·행동 근거·인과 앵커     │
│            │                                      │                     │
│            └──────────── 하모나이제이션(공통 페르소나 스키마) ──────────┘    │
│                                  │                                       │
│             ┌────────────────────┼─────────────────────┐                 │
│             ▼                    ▼                     ▼                 │
│        임베딩(한국어)        KuzuDB 그래프          agent_runner(Claude)    │
│             └──────── /v1/query · /v1/simulate · /v1/policy ─────────┘    │
└────────────────────────────────────────────────────────────────────────┘
```

**Tier 1 — 정적 페르소나 (Nemotron-Personas-Korea)**
- 6~7M 합성 페르소나에서 **"거주지=서울 + 연령 18~35세"** 로 필터해 서울패널과 동일 모집단 세그먼트 구성(서울패널 확인값: 만 18–35, 출생 1986–2003, 5개 권역).
- 구조화 필드(성별·연령·혼인·학력·직업·거주지) + 자연어 서사를 그대로 system-prompt 그라운딩에 사용.
- **역할**: 대표성 있는 "모집단 캔버스", 세그먼트 분석, 디지털 트윈이 비어 있는 인구 셀의 빈틈 메우기, 다양한 페르소나 문체로 스트레스 테스트.

**Tier 2 — 디지털 트윈 (서울청년패널)**
- v2의 페르소나 빌더로 실응답자 → 자서전 + 2시점 궤적 + **정책 이용/만족 사실**을 보유한 에이전트.
- **역할**: 정책 반사실 질의에 자기 궤적 근거로 응답(생성형), 그리고 **실제 1차→2차 변화가 정량 근거(evidence)** 가 되는 인과 앵커.
- "디지털 트윈"으로 부르되, **2시점 관측 기반**임을 명시(밀집 종단이 아니므로 외삽은 신중히).

## 3. 하모나이제이션 레이어 (두 스키마를 하나로)

두 데이터는 변수 체계가 다르므로 **공통 페르소나 스키마 + 크로스워크**가 필수입니다. `backend/persona_schema/`.

| 공통 필드 | Nemotron(정적) | 서울패널(트윈) | 처리 |
|---|---|---|---|
| 성별 | sex | `sex`(1남/2여) | 라벨 통일 |
| 연령 | age | `age01/02` | 18–35 필터 정합 |
| 학력 | education | `p01edu`(고졸이하~대학원) | 학력 분류 매핑 사전 |
| 직업/경제활동 | occupation | `p01eco`+`p01c13`(직종) | 직업 분류 크로스워크(KSCO 등) |
| 거주지 | residential_area | `region01`(5권역) | 서울 권역 매핑 |
| 혼인/가구 | marital_status | `p01htype`(가구유형) | 근사 매핑 |
| 서사 | persona narrative | 자서전 MD(자동생성) | 동일 텍스트 슬롯 |
| **정책이용** | (없음) | `k`-계열 이용/만족 | **트윈 전용 필드**(정적엔 결측, 투영 대상) |
| **궤적/결과** | (없음) | 소득·삶만족·우울 1·2차 | **트윈 전용**(인과 근거) |

> 핵심: 정적 페르소나는 정책·궤적 필드가 **구조적으로 비어 있음**. 이 빈칸이 §4의 "투영" 대상이며, 절대 실측값처럼 다루지 않도록 `source: synthetic|observed` 플래그를 모든 레코드에 부착.

## 4. 정책 시뮬레이션 설계 — 두 패널의 결합 방식

역할 분담을 지킨 채 결합하는 **두 가지 핵심 패턴**을 권장합니다.

### 4-A. 깊이→폭 투영 (Twin → Static Transfer) ★메인
1. **근거 추정(트윈)**: 정책 이용군의 실제 1차→2차 변화(소득·취업·삶만족, `long_w2` 가중)와 트윈 에이전트의 반사실 응답으로 **정책 반응 패턴**을 도출.
2. **투영(정적)**: 인구 셀(성별×연령×학력×권역) 단위로 그 반응을 **데모그래픽 유사도 기반으로 정적 페르소나 모집단에 임퓨테이션** → "누가, 얼마나 영향을 받는가"의 **모집단 규모 분포 추정**.
3. 결과는 항상 **`projection`(투영, 측정 아님)** 으로 라벨링하고 트윈 근거를 함께 표기.
- 산출 예: *"청년수당을 서울 청년 전체로 확대 시, 18–24세 저학력 미취업 세그먼트에서 취업 전환 체감이 가장 크게 투영됨 — 근거: 트윈 N명의 실제 미취업→취업 전환 + 반사실 응답."*

### 4-B. 대표성 보정 / 빈칸 메우기 (Static as Reference)
- 정적 페르소나 분포를 기준으로 **트윈 표본의 대표성**을 점검(어떤 인구 셀이 과소·과대 표집됐는지).
- 트윈이 희박한 셀은 정적 페르소나로 **시나리오 커버리지를 보완**(단, 그 셀의 정책 응답은 4-A 투영으로만).

### 4-C. 모드 매핑 (설계 문서 `/v1/simulate`에 통합)
- `individual` / `discussion`(연구자 다중 라운드)는 그대로. 각 발화 페르소나에 `persona_type: static|digital_twin` 표기.
- **신규 `/v1/policy/simulate`**: 정책·시나리오·타깃 세그먼트를 받아 4-A 투영 + 트윈 evidence를 묶은 응답 반환.

## 5. 개정 로드맵 (설계 문서 파일 매핑)

| Phase | 내용 | 산출/파일 | 기간 |
|---|---|---|---|
| **A. 트윈 빌더** | 서울 `.dta`+코드북 → 자서전·궤적·정책필드(v2 검증 완료) | `persona_builder/` | 3~4일 |
| **B. 정적 로더/필터** | Nemotron-Personas-Korea 로드 → 서울·18~35 필터 → 공통 스키마 매핑 | `static_personas/` | 2일 |
| **C. 하모나이제이션** | 학력·직업·권역 크로스워크 사전, `source`/`persona_type` 플래그 | `persona_schema/` | 2일 |
| **D. 임베딩(한국어)** | `ko-sroberta`/`bge-m3`로 교체, 두 계층 공통 임베딩 | `embeddings.py` | 1일 |
| **E. KuzuDB 그래프** | 정책 이용을 엣지로(트윈), 정적은 데모그래픽 노드 | `persona_retriever.py` | 2일 |
| **F. 에이전트 한국어화·그라운딩** | 자서전/Nemotron 서사 주입, 환각 가드 | `agent_runner.py` | 2일 |
| **G. 정책 시뮬레이션(4-A/B)** | 투영 엔진 + evidence, `/v1/policy/simulate` | 신규 모듈 | 3~4일 |
| **H. Demo UI** | persona_type 배지, 2시점 궤적, 정적/트윈 토글, 투영 면책 표기 | `page.tsx`, `TrajectoryChart.tsx` | 2~3일 |

권장 순서: **A → B → C → D → F → G(4-A) → E/H**. (트윈이 근거 앵커라 먼저, 정적은 확장이라 그다음.)

## 6. 리스크 & 가드레일

- **합성의 타당성 경계(최重要)**: 정적 페르소나는 인구분포는 맞아도 정책 인과는 없음 → 정책 결과는 **반드시 트윈 근거 + `projection` 라벨**. UI/API 문서에 "정적 페르소나 응답은 합성 추정"임을 명시.
- **이중 환각 중첩**: Nemotron 서사(LLM 생성) + 에이전트 응답(LLM 생성) → 그라운딩 프롬프트 + "자료에 없으면 모른다"가드 + 트윈은 자서전 사실 고정.
- **2시점 디지털 트윈**: 밀집 종단이 아님 → 외삽·장기효과 주장 금지, "2개 관측 시점 기반"임을 표기.
- **라이선스/컴플라이언스**: Nemotron-Personas는 CC BY 4.0 계열(상업 사용 가능, 출처표기). **서울청년패널 원자료의 이용약관(특히 B2B API 상업 재배포 가능 여부)은 별도 확인 필수** — 설계 문서의 per-query/구독 과금과 직결.
- **대표성 정합**: 트윈은 `long_w2` 가중, 정적은 PGM 인구 정합 → 모집단 추정 시 기준 모집단을 일치시켜 이중계산 방지.
- **세그먼트 정합 오차**: Nemotron 필터(서울·18~35)와 서울패널 정의의 미세 차이(권역 코딩·연령 경계) → 크로스워크 검증 테스트.

## 7. 결정 필요 사항

1. **정적 페르소나 규모**: 필터 후 전수 vs 대표 표본(예: 트윈과 1:N 매칭 5,000~50,000명). 비용·검색 품질 트레이드오프.
2. **투영 방식**: 셀 평균 임퓨테이션 vs 유사도 가중 vs 간단한 모델(트윈으로 학습한 반응함수). MVP는 셀 평균부터.
3. **트윈 표본 수**: v2 권장 200~300명 유지 여부.
4. **임베딩 모델**: 로컬(`bge-m3`) vs API.
5. **서울패널 상업 이용 약관 확인 주체/일정**.

그리고 v2와 동일하게, social-labs의 현재 `agent_runner.py` 프롬프트·KuzuDB 스키마·자서전 샘플 1개를 주시면 위 Phase들을 실제 함수에 1:1로 붙여 코드 작업지시서로 만들겠습니다.

---

### 요약
제안하신 **정적(Nemotron) + 디지털 트윈(서울패널)** 2계층은 설계 문서 비전과 정합하고, 서울패널의 표본·시점 한계를 Nemotron의 대표성으로 보완하는 좋은 구조입니다. **단 하나의 원칙** — 정책효과의 *근거는 트윈(실데이터)에서만*, 정적 페르소나는 그 패턴을 *투영받아 폭을 확장*하는 역할 — 을 아키텍처·API·UI에 못박으면, "폭 × 깊이"를 모두 갖춘 한국형 정책 시뮬레이션 엔진이 됩니다. 정책 결과는 항상 `projection`/`evidence`를 함께 제시해 합성과 실측의 경계를 투명하게 유지하세요.
