# social-labs 정책 시뮬레이션: NLSY97 → 서울청년패널 이식 구현 계획 (v2, 개정)

> 개정 사유: 업로드해 주신 `persona-api-mvp-design.md`로 저장소의 정체가 확인됨.
> social-labs는 DiD·매칭 같은 **계량 인과추론 도구가 아니라**, 패널 응답자를
> **LLM 페르소나 에이전트 군**으로 변환해 질의·시뮬레이션하는 **페르소나 에이전트 API**다.
> 따라서 "정책효과 시뮬레이션"의 의미와 구현 방식을 이 아키텍처에 맞게 다시 정의한다.

---

## 1. 무엇을 만드는가 — 재정의

설계 문서 기준 social-labs의 파이프라인은 다음과 같습니다.

```
패널 원자료 → 페르소나 자서전(MD) → ① 임베딩(시맨틱 검색)
                                  → ② KuzuDB 지식그래프(구조 필터)
                                  → ③ agent_runner(Claude로 에이전트 응답)
        ↑                                   ↓
   NLSY97 (현재)               /v1/query · /v1/simulate · /v1/personas/{id}/trajectory
```

이 구조에서 **"정책효과 시뮬레이션"은 회귀계수 추정이 아니라**, 실제 청년의 궤적에 근거해 만들어진 페르소나 에이전트에게 정책 시나리오를 던져 **"이 정책을 받으면/받았다면 삶이 어떻게 달라지는가"를 에이전트가 응답·토론하게 하는 것**입니다(연구자 모드의 다중 라운드 토론 포함). 즉 **에이전트 기반(agent-based) 정성·탐색적 시뮬레이션**이며, 여기에 패널의 실제 사전/사후 변화를 근거로 덧붙일 수 있습니다.

따라서 작업의 본질은 **"NLSY97 자서전 100개를 서울청년 자서전으로 갈아끼우고, 그 위 검색·에이전트·궤적·UI를 한국 데이터에 맞게 현지화하는 것"** 입니다.

## 2. NLSY97 → 서울청년패널: 파이프라인에 미치는 차이

이 차이들이 이번 이식 작업의 난이도와 설계 결정을 결정합니다.

| 차원 | NLSY97 | 서울청년패널 | 파이프라인 영향 |
|---|---|---|---|
| **궤적 길이** | 1997–2019, **22년 다회차** | **2시점(1차·2차)** 뿐 | ★최대 이슈. "22년 종단 궤적 에이전트"가 2점 궤적이 됨. 자서전이 짧아지고 trajectory 차트도 2포인트. → 서사 전략 재설계 필요(§5) |
| **페르소나 수** | 자서전 100개 | 6,515명(패널완결 ~3,762명) | 100명만 뽑을지/대량 생성할지 표본 전략 필요(§4) |
| **언어** | 영어 | **한국어** | `all-MiniLM-L6-v2`는 한국어 성능 취약 → 한국어/다국어 임베딩으로 교체 필수(§3-B) |
| **정책 변수** | 일반적 | `k`-계열: 정책별 **인지·이용·이용의향**(2차 **만족도**) | ★강점. 페르소나가 "내가 어떤 정책을 썼고 만족했는지"를 사실로 보유 → 정책 시뮬레이션 그라운딩이 매우 탄탄 |
| **코드북** | NLS Investigator | 업로드된 CSV(1,776변수 값라벨 완비) | 구조화 응답 → 자연어 자서전 **자동 생성 가능**(§5) |
| **소득 단위** | USD 연소득 | **만원·월평균** | 스키마/표시 단위 정규화 |
| **가중치** | 패널 가중치 | `cross_w1/w2`, **`long_w2`(종단)** | 모집단 추정·대표성 표본 추출에 사용 |

## 3. 구현 로드맵 (설계 문서의 실제 파일에 매핑)

### Phase A — 페르소나 빌더: 구조화 `.dta` → 자서전 + 궤적 (★신규 코어, 3~4일)
NLSY97의 "자서전 100개 MD"를 대체하는 **가장 중요한 단계**. `backend/persona_builder/` 신설.

1. **표본 선정**(§4): 종단 완결·가중치 보유 표본에서 대표성 있게 추출.
2. **코드 디코딩**: 업로드된 코드북 CSV(`Variable Name, Value Code, Value Label`)를 룩업 사전으로 로드 → 모든 코드값을 한국어 라벨로 치환.
3. **자서전 MD 생성**: 인구학·학력·경제활동·소득·주거·가구·심리(삶만족/CES-D)·**정책 이용 이력**을 1차→2차 변화 서사로 템플릿 렌더링(예시 §5). NLSY와 동일하게 `output/personas/SYP_xxxx.md`로 저장.
4. **궤적 JSON 생성**: `/v1/personas/{id}/trajectory` 스키마에 맞춰 2시점 timeline(소득·경제활동상태·삶만족·정책이용 이벤트) 출력.

### Phase B — 임베딩 한국어화 (`embeddings.py`, 1일)
- `all-MiniLM-L6-v2` → **한국어/다국어 모델로 교체**. 후보: `jhgan/ko-sroberta-multitask`, `BAAI/bge-m3`(다국어·로컬), 또는 Claude/OpenAI 다국어 임베딩 API.
- `output/embeddings.npy` 캐시 로직은 그대로. 모델 교체에 따라 임베딩 차원만 바뀌므로 재생성 1회.
- 코사인 유사도 Top-K 검색 로직은 무변경.

### Phase C — KuzuDB 지식그래프 스키마 재정의 (`persona_retriever.py` 2단계 중 구조 필터, 2일)
- 노드/엣지 스키마를 서울 변수로 재설계: `(:Persona)-[:LIVES_IN]->(:Region)`, `-[:USED_POLICY {wave, satisfaction}]->(:Policy)`, `-[:HAS_EDU]->(:Education)`, `-[:ECON_STATUS {wave}]->(:Status)` 등.
- Cypher 필터를 한국 필드(권역·최종학력·경제활동상태·정책이용)로 교체. **정책 이용 여부가 그래프 엣지로 들어가므로** "청년수당 이용자 중 30대 여성 1인가구" 같은 정책 코호트 질의가 구조 필터로 바로 가능.

### Phase D — 에이전트 러너 현지화 (`agent_runner.py`, 1~2일)
- 시스템 프롬프트 한국어화 + **페르소나 그라운딩**: 자서전 MD를 컨텍스트로 주입하고 "당신은 이 사람입니다. 이 사실에서 벗어나지 마세요"로 환각 억제.
- `individual` / `discussion`(다중 라운드) 모드 로직은 유지. 모델은 `claude-opus-4-8` 등 한국어 강한 모델 사용.

### Phase E — 정책효과 시뮬레이션 모드 (★이번 요청의 핵심, 2~3일)
§6에서 상술. `/v1/simulate`에 정책 시나리오 프리셋을 추가하고, 선택적으로 정량 근거(사전/사후 대조)를 함께 반환.

### Phase F — API 스키마/라벨 매핑 (`main.py`, `app.py`, 1일)
- 설계 문서의 `/v1/` 계약(`query`/`simulate`/`trajectory`) 유지, 내부만 서울 데이터로 교체.
- `background` 필드를 한국 항목으로(성별·출생연도·최종학력·권역·가구유형), `timeline`을 2시점으로.

### Phase G — Demo UI 현지화 (`page.tsx`, `TrajectoryChart.tsx`, 2일)
- 입력 예시·페르소나 카드·조언 패널 한국어화, 통화 만원(₩) 표기.
- `TrajectoryChart`는 2포인트(1차·2차) + 정책이용 이벤트 마커로 단순화. 일반/연구자 모드 토글 유지.

## 4. 페르소나 표본 전략 (NLSY의 "100개"를 어떻게 대체할까)

세 가지 선택지를 제시합니다. MVP는 **B안** 권장.

- **A. 전수(~3,762명)**: 검색 품질 최고, 임베딩·LLM 비용·관리 부담 큼.
- **B. 대표 표본 200~300명**(권장): `long_w2` 가중·층화(성별×연령×학력×권역×정책이용)로 추출해 모집단 대표성 확보. NLSY 100개 대비 정책 코호트까지 커버.
- **C. 정책 코호트 중심 표본**: 시뮬레이션 대상 정책(청년수당·청년월세·마음건강 등) 이용자/유사 미이용자를 의도적으로 포함해 대조 시뮬레이션 최적화.

## 5. 자서전 생성: 실제 1명으로 검증한 예시

코드북 라벨로 디코딩해 실제 응답자 1명(식별번호 익명화 `SYP_0001`)을 렌더링한 결과입니다. **2시점이지만 "미취업→취업, 삶의만족 6→8, 청년수당 이용 후 이듬해 청년월세 이용"이라는 변화 서사가 충분히 살아납니다.**

**자서전 MD (발췌 템플릿)**
```markdown
# SYP_0001
저는 1988년생 여성으로, 서울 도심권에서 1인가구로 살고 있습니다.
전문대(예체능계열)를 졸업했습니다.

## 1차 조사 시점
당시 저는 학교를 다니지 않으면서 일자리도 없는 상태였습니다(비재학 미취업).
개인 월소득은 약 300만 원이었고, 삶에 대한 만족도는 10점 만점에 6점이었습니다.
이 무렵 저는 서울시 '청년수당'을 이용했습니다.

## 2차 조사 시점 (약 1년 후)
저는 취업에 성공했습니다. 개인 월소득은 250만 원으로 다소 줄었지만,
삶의 만족도는 8점으로 올랐습니다. 이 시기에는 '청년 임차보증금(월세) 지원'을 이용했습니다.

## 회고
일자리가 없던 시기 청년수당이 버팀목이 되었고, 이후 주거 지원으로 옮겨가며
생활의 안정을 찾아가는 과정이었습니다.
```

**궤적 JSON (`/v1/personas/SYP_0001/trajectory`)**
```json
{
  "id": "SYP_0001",
  "background": { "sex": "여성", "birth_year": 1988, "education": "전문대 졸업",
                  "region": "도심권", "household": "1인가구" },
  "timeline": [
    { "wave": 1, "econ_status": "비재학 미취업", "income_manwon": 300,
      "life_satisfaction": 6, "policies_used": ["청년수당"] },
    { "wave": 2, "econ_status": "취업", "income_manwon": 250,
      "life_satisfaction": 8, "policies_used": ["청년 임차보증금 지원"] }
  ]
}
```
> 이 변환은 코드북 룩업으로 전 표본에 자동 적용됩니다. 1,776변수 중 페르소나에
> 의미 있는 ~40~60개(인구학·학력·경제활동·소득·주거·심리·정책)를 선별해 템플릿화합니다.

## 6. 정책효과 시뮬레이션 설계 (이번 요청의 본질)

페르소나 에이전트로 정책효과를 "시뮬레이션"하는 세 가지 모드를 권장합니다.

### 6-A. 반사실 질의 (개인 모드)
정책 **미이용** 페르소나에게: *"만약 청년수당을 받게 된다면 구직과 생활이 어떻게 달라질 것 같나요?"* → 본인의 실제 처지(자서전)에 근거한 응답. 반대로 **이용자**에게는 *"청년수당이 없었다면?"* 반사실을 질문.

### 6-B. 대조 코호트 토론 (연구자 모드, discussion)
KuzuDB 구조 필터로 **이용군 vs 유사 미이용군** 페르소나를 각각 뽑아 다중 라운드 토론. 예: 청년수당 이용 후 취업한 `SYP_0001` vs 비슷한 조건의 미이용자 → 정책의 체감 효과·한계를 대화로 드러냄.

### 6-C. 정량 근거 백본 (선택, 신뢰도 강화)
에이전트 응답에 **실제 패널의 사전/사후 대조**를 근거로 첨부. 정책 이용군의 1차→2차 평균 소득·취업률·삶만족 변화(가중)를 계산해 `/v1/simulate` 응답에 `evidence` 필드로 동봉 → "에이전트의 말 + 데이터 근거"를 함께 제시. (이것이 v1 계획의 DiD/매칭이 **보조 근거 레이어**로 재배치되는 지점입니다.)

**정책 시나리오 프리셋**(2시점 모두 측정되어 시뮬레이션이 바로 되는 것):
청년수당(`k26`), 청년월세지원(`k24`), 청년 임차보증금, 서울시 마음건강 지원(`k28`), 국민취업지원제도(`k53`), 희망두배 청년통장(2차 `k2q7`).

## 7. 리스크 & 주의사항

- **2시점 궤적의 빈약함**: NLSY의 22년 서사에 비해 정보 밀도가 낮음. → 자서전에 1차 회고형 문항(첫 일자리·교육경험·구직 어려움 등 단면 정보)을 함께 엮어 깊이를 보강. UI에서 "2개 시점 패널"임을 명시.
- **한국어 임베딩**: 영어 모델 그대로 쓰면 검색 품질 급락 → §3-B 교체 필수.
- **환각(페르소나 일탈)**: 에이전트가 자료에 없는 사실을 지어낼 위험 → 자서전 그라운딩 + "모르는 건 모른다고" 프롬프트 가드.
- **반사실의 한계**: 6-A/6-B는 **인과 추정이 아니라 탐색적 시뮬레이션**임을 UI·API 문서에 명시(연구자 모드 면책 문구). 정량 인과가 필요하면 6-C 백본 또는 별도 DiD 모듈로.
- **소표본 정책**: 이용자 수십 명대 정책은 6-C 근거 통계가 불안정 → 신뢰구간 표기/제외.
- **개인정보**: 패널은 비식별 자료지만, 페르소나 ID·서사 결합으로 재식별 위험 최소화를 위해 PID는 `SYP_xxxx`로 익명화·매핑.

## 8. 권장 진행 순서 (MVP 1~2주)

1. **Phase A 페르소나 빌더** + 코드북 룩업으로 **200~300명 자서전·궤적 자동 생성** (가장 큰 가치, 먼저).
2. **Phase B 한국어 임베딩** 교체 → `/v1/query` 동작.
3. **Phase D 에이전트 한국어화** → `/v1/simulate` individual.
4. **Phase E 정책 시뮬레이션 모드(6-A)** → 핵심 요구 충족.
5. Phase C KuzuDB + 6-B 토론, Phase G UI, 6-C 정량 백본 순으로 확장.

## 9. 지금 공유해 주시면 코드 단위로 확정해 드릴 것

설계 문서로 아키텍처는 명확해졌습니다. 아래만 있으면 위 계획을 실제 함수·스키마에 1:1로 붙입니다.

1. NLSY 자서전 MD **1개 샘플**(템플릿·문체·섹션 구조 맞추기) 및 `output/personas/` 경로 규칙
2. 현재 KuzuDB 스키마(노드/엣지 정의, 기존 Cypher) — 서울 스키마로 변환 위해
3. `agent_runner.py`의 현재 시스템 프롬프트(한국어화·그라운딩 위치 파악)
4. `embeddings.py`가 자서전을 어떤 텍스트 단위로 임베딩하는지(전체/청크)
